# 组件库与补图

## 1. 先建立语义清单

组件库当前包含 260 个可组合元素：15 个背景、73 个角色姿态、22 个关系群像、42 个场景模块和 108 个道具。它覆盖常见商业、服务、教育、数字运营、医疗接待、金融服务和分发场景，但不会预先覆盖所有题材。目录、索引字段、查找方式和分辨率边界见[组件库使用说明](../assets/component-library/README.md)。

每个新项目先从文案列出：

1. 反复出现的角色身份与必要姿态；
2. 必须建立空间关系的场景；
3. 会被移动、交换、增减或替换的有机道具；
4. 应由代码生成的文字、数字、流程、表格和路径。

## 2. 三种实现方式

把清单中的每个元素放进三类之一：

| 方式 | 适合内容 |
|---|---|
| 复用组件 | 已有角色姿态、背景、群像、模块和有机道具 |
| 代码生成 | 文字、数字、表格、图表、流程节点、箭头、路径、边框和精确布局 |
| ImageGen 补图 | 缺少的角色姿态、关系群像、专业环境、复杂设备或难以用代码表达的有机对象 |

现有组件能清楚表达动作就复用。只有缺少因果链中不可替代的对象时才补图，不因为画面空而生成装饰。

## 3. 先分来源，再进入对应质检

每个图片候选先记录 `source_kind`，不能把不同来源的缺陷混成同一个问题：

| `source_kind` | 前置条件 | 应做的检查 | 问题归属 |
|---|---|---|---|
| `component-library` | 组件库文件已经存在 | 使用前检查源 PNG | 现有组件问题 |
| `user-provided` | 用户提供的图片已经存在 | 使用前检查源图，不改写来源责任 | 用户提供资产问题 |
| `imagegen` | 已确定缺口，并且 ImageGen 已真实生成文件 | 对生成结果做出图质检 | ImageGen 生成结果问题 |

如果没有合适的现有图，也还没有调用 ImageGen，状态只能是“待生成”，此时没有图片可质检，不能写“出图质检通过”。正确顺序是：

```text
盘点现有图 → 输入质检 → 能用则复用
                         ↓不能用或确实缺图
                    调用 ImageGen → 输出文件落盘 → 出图质检
                                                        ↓通过
                                                   进入组件库或项目
```

代码文字、流程、表格和路径不走透明 PNG 源图质检；它们在真实渲染后检查布局、裁切和可读性。

## 4. 选择组件的顺序

1. 先选舞台背景或图解模式；
2. 再选承担动作的主体姿态；
3. 选择被移动、交换、比较或替换的对象；
4. 增加能证明结果的组件；
5. 最后才考虑装饰和转场前景。

每个组件都要对应当前旁白中的一个名词、动作、关系或结果。关闭字幕后，观众仍应大致看懂谁对什么做了什么。

## 5. ImageGen 补图和出图前置条件

只有语义清单中缺少不可替代的角色姿态、群像、环境或有机道具时才进入本节。先调用 ImageGen 并取得真实输出文件，再谈出图质检；提示词、生成请求或等待状态都不算图片产物。

补图时同时提供角色身份参考和整套画风参考，并明确：

- 资产用途和语义动作；
- 主体、姿态、手部和对象接触关系；
- 是否需要真实透明背景；
- 必须保持的身份、服装、比例、描边、纸张纹理和色彩；
- 禁止文字、水印、棋盘格、阴影、裁肢和额外对象。

一个角色姿态只解决一个明确动作。复杂关系可以生成群像，但文字、数字和精确流程仍由代码添加。

## 6. 透明 PNG 源图质检

- 人物完整身体、道具完整轮廓，四周保留透明余量；
- 不含背景、文字、水印、棋盘格或烤字；
- 不夹带相邻格的半只手、半个头、半台设备；
- 群像逐人检查，不允许贴边裁肢；
- 同角色保持身份、服装、比例、描边、主光和色彩一致；
- 图片生成结果不满足一致性时，改用现有干净姿态，不强行接入。

“看起来像透明”的棋盘格图片不算透明资产。必须读取 PNG alpha，确认背景像素确实透明，并把图片合成到浅色和深色背景上检查残边。

对已经存在的组件或用户提供图，质检属于输入检查；对 ImageGen 图片，必须等生成结果落盘后才运行。先把待验收文件放在任务工作区，不要直接加入组件库。运行时明确来源：

~~~bash
python3 scripts/inspect_transparent_assets.py /path/to/generated-assets \
  --source-kind imagegen \
  --output /path/to/task/asset-review/report.json \
  --preview-dir /path/to/task/asset-review/previews
~~~

检查已有组件时改用 `--source-kind component-library`，检查用户提供图时改用 `--source-kind user-provided`。报告中的来源必须与真实输入一致。

脚本只做最小预筛：真实 alpha、空图、可见内容边界和贴边风险，并生成浅底/深底并排预览。不要为画面质量继续堆单元测试、阈值或评分；必须逐张以原尺寸打开预览，确认：

- 单人没有缺头、缺手、缺脚、断关节或贴边裁肢；
- 群像中的每个人都完整，没有相邻格残片；
- 道具、设备和前景的完整轮廓存在，没有被生成模型截断；
- 透明区没有白边、棋盘格、残影和多余对象；
- 四周留有足够透明余量，后续缩放和运动不会立即撞边。

`ok` 只代表程序没有发现 alpha 和贴边问题，不代表人物或道具在语义上完整。`--strict` 只适合批量预筛，不能代替看图。预览没实际打开，资产就不算通过。贴边警告不能靠裁掉更多像素解决；先判断生成结果是否已残缺，残缺就重新生成或换图。

新资产加入 `assets/component-library/` 后运行：

~~~bash
python3 scripts/build_component_catalog.py
~~~

然后重新创建项目，或把新文件同步到对应工程：Remotion 使用 `public/media/house-components/`，HyperFrames 使用 `assets/house-components/`。

## 7. 源图完整不等于成片完整

PNG 本身通过 alpha 和边缘检查后，还要看它进入真实构图后的结果。`overflow: hidden`、`object-fit`、容器尺寸、负坐标、缩放中心、遮罩和转场都可能把干净源图再次切断。

先分清两类问题：

- 单独打开已有或用户提供 PNG 就有半只手、相邻格残片或白边：拒绝该输入，换已有干净图；确实缺图时再调用 ImageGen；
- ImageGen 输出 PNG 本身残缺：拒绝该生成结果并重新生成或换方案；
- 源 PNG 完整，只有某个构图或动画时被切：查容器、位移、缩放、遮罩和前后层级。

实际渲染后先用接触页定位时间，再导出可疑时间的高清单帧检查边缘，不能只看组件目录里的原图。

当前组件库主要面向 1920×1080 成片。是否适合更高分辨率必须读取 `catalog.json` 中每张图的 `width` 和 `height` 判断；直接把 1080p 位图工程导出成 4K 不会增加真实细节。

## 8. 何时通常不需要视频模型

当运动主要是独立图层进入、姿态替换、对象移动、遮罩、转场、文字和图解构建时，Remotion 或 HyperFrames 能精确控制这些动作。是否增加其他生成工具取决于画面需求、可编辑性和用户选择。
