# 参考片进入与拉片

参考片的作用是帮助理解表达方法，不是提供可以直接复制的镜头。只处理用户有权下载、分析或引用的媒体，并按用户给出的样本范围执行。

## 1. 获取样本和证据

工具可接收一个或多个链接；当任务明确包含播放列表或主页范围时才使用 `--playlist`，并可用 `--max-downloads` 限制样本数量。

```bash
python3 scripts/fetch_reference.py "<URL1>" "<URL2>" --output-dir /path/to/task/reference
python3 scripts/probe_reference_media.py /path/to/task/reference/video.mp4 --output-dir /path/to/task/reference/evidence
```

需要登录时，优先使用 `--cookies-from-browser chrome`，不要求额外安装浏览器扩展。只有确实需要独立 cookie 文件时，才选择自己信任的本地导出工具，把 `cookies.txt` 保存在仓库外并通过 `--cookies /absolute/path/cookies.txt` 传入。

`probe_reference_media.py` 生成媒体信息、接触图和音频波形，只用于定位。拉片结论必须来自实际观看原视频。

## 2. 四遍观看法

1. **完整观看**：先不暂停，记录视频解决什么问题、开头怎样吸引、章节如何推进、结尾怎样收束。
2. **画面观看**：关注背景复用、主体位置、景别、层级、遮挡、字幕安全区和镜头交接。
3. **动作观看**：逐句记录人物姿态、道具接力、状态替换和进入/退出；区分真正的语义动作与无意义漂浮。
4. **声音观看**：记录旁白换意、停顿、重音、音效和标题卡怎样共同形成节拍。

## 3. 逐段记录

对每个实际发生变化的时间段记录：

| 字段 | 要回答的问题 |
|---|---|
| 时间码 | 这一段从哪里开始，到哪里结束？ |
| 旁白锚点 | 哪句话触发了画面变化？ |
| 舞台 | 是环境场景、图解面板还是标题卡？ |
| 主体与对象 | 谁在做什么，作用于哪个对象？ |
| 可见动作 | 进入、接触、交换、替换、组建还是退场？ |
| 结果 | 动作完成后，观众看到了什么新状态？ |
| 制作方式 | 哪些由透明图片完成，哪些由代码文字、路径或图形完成？ |
| 声音 | 旁白、音效和转场怎样配合？ |

切点数量、像素变化和自动检测只能辅助定位，不能代替判断。镜内构图明显重组时，即使没有硬切，也要作为新的画面节拍记录。

## 4. 提炼方法，不复制内容

拉片结束后，把观察结果写成与原作者身份无关的方法摘要：

- 稳定不变的视觉世界：画风、色彩、字幕、标题卡、角色体系；
- 持续变化的组合：姿态、道具、关系、景别、前景和结果状态；
- 可复用的运动语法：建立、接触、交换、替换、组建、退场；
- 图片与代码的边界：有机角色/道具用图片，精确文字/数字/路径用代码；
- 当前新文案可以继承什么，必须重新设计什么。

新片不得复制来源身份、台词、配音、字幕、水印或连续镜头顺序。
